# 钉钉考勤加班分析工具

用于分析钉钉考勤导出 Excel 的工具，提供 Windows 桌面窗口和命令行，可打包成 ZIP 交给 HR 使用。

## 当前范围

- 读取钉钉导出的 `.xlsx` / `.xlsm` 考勤文件。
- 以 `每日统计` 作为每日考勤主表。
- 以 `原始记录` 查找每个人每天的首个和最后一个有效打卡。
- 输出包含加班明细、员工汇总、每日汇总、待补卡通知、待审核清单、异常数据、待人工确认和配置留痕的分析 Excel。

## 考勤规则（简版）

- **工作日**：09:00-10:00 弹性上班、弹性下班；09:00 前到按 18:00 下班，09:30 到按 18:30，10:00 及以后到按 19:00，不因迟到顺延。加班从标准下班后扣除 30 分钟晚餐，再按最后有效打卡计算。
- **休息日/节假日**：按首末有效打卡计算，扣除固定午休 12:00-13:30；晚餐默认不扣。班次含“休息”或日期在 `holiday_dates` 中时按非工作日处理。
- **节假日区分**：只有 `holiday_dates` 明确配置的日期归为法定节假日；其余“休息”班次统一归休息日，不按星期推断法定节假日。
- **公司放假**：通过“编辑公司放假”维护，支持全天、上午、下午；对全员生效。放假部分免考勤、不计迟到或请假；实际工作按休息日加班并核对审批，法定节假日和原休息班次仍优先。
- **迟到和请假**：迟到按分钟统计；每月前 3 次、合计 30 分钟以内宽限，首次迟到 45 分钟时宽限 30、计扣 15 分钟。请假按审批实际区间逐日扣除固定午休，每天最多 7.5 小时，休息日不计请假；不按班次 09:30 裁切，不采用审批尾部标注小时数。审批可抵扣迟到，午休不计迟到；请假与加班分别保留，交 HR 审核是否同时计薪。
- **工资分类**：年假、调休不扣工资，事假计入扣工资请假；外出、出差计出勤，不计请假；病假、婚假和通用“请假”的工资分类尚未确认，单列并交 HR 审核。
- **审批**：工作日不要求加班审批；休息日和节假日需要审批，审批与实际相差超过 30 分钟时通知 HR 审核。
- **首末打卡**：原始有效打卡优先；不足两个不同打卡时间时，尝试每日统计中第 1/2/3 段打卡兜底，仍按首末有效卡计算，不扣中间离开时长。有效打卡不足时不计加班并列入待补卡；跨午夜按原始表的“考勤日期”归属。
- **输入报错**：缺表/缺列/重复列、未知审批、未知打卡结果、非法或无法完整解析的日期时间、重复员工日记录、无法归属的原始打卡、公式及错误单元格均报错。一次列出工作表、行号、字段、原始值和原因；该文件不生成统计结果，命令行退出码为 4。配置格式或类型错误退出码为 2。

完整规则、实际样本发现、支持/拒绝的格式和未覆盖边界见 [考勤规则核查](docs/attendance_rules_review.md)。

## 运行

给 HR 使用时，发送一键打包得到的 ZIP，完整解压后双击 `dingding-attendance.exe`，无需安装 Python。窗口选择考勤输入目录和结果输出目录，批量处理输入目录第一层的全部 `.xlsx` / `.xlsm` 考勤文件，跳过 Excel 临时文件和已有分析报表。支持内置规则编辑弹窗、显示处理阶段、打开本次结果和日志。详细步骤见 [HR 使用说明](docs/HR使用说明.txt)，交互及错误处理设计见 [HR 交互方案](docs/hr_interaction.md)。

在有 Python 的开发环境中，运行 `python main.py` 打开同样的窗口；也可继续双击项目根目录的 `run_attendance.bat` 使用命令行批量统计，报错后窗口会保留。

也可以在命令行中运行：

```powershell
python -m attendance_analyzer.cli
```

命令行会批量分析 `input` 中所有 `.xlsx` 和 `.xlsm` 文件，并将结果写入 `output` 目录。文件名包含配置后缀 `_加班分析` 的已有结果文件会被跳过。同名的 `.xlsx` 和 `.xlsm` 会在开始处理前报错，请先重命名其中一个，避免结果覆盖。窗口模式每次在选定结果目录中新建带时间的子目录，避免与旧结果混淆。

同一员工每个自然月须使用一份完整考勤文件；迟到宽限在各文件内独立分配，不支持拆月后分别计算。

仍可只分析一个指定文件：

```powershell
python -m attendance_analyzer.cli "input\2026.5考勤.xlsx" -c config.json
```

## 在窗口中配置规则

点击“编辑考勤规则”，在“工作表、工作日、加班、非工作日、报表”标签页中修改中文表单。全部 22 项原有配置均可编辑，每项附有说明；非工作日加班使用勾选开关，取整方式使用下拉框。点击“保存并关闭”后，下次统计立即生效，无需安装 Excel/WPS 或重新打包。

- 时间填写 `09:00` 或 `09:00:00`；分钟和次数只填整数，不加单位。
- 法定节假日填写完整日期，例如 `2026-10-01;2026-10-02`；多个日期、关键字、前缀用分号分隔。
- 法定节假日、休息班次关键字、无效打卡前缀可留空，表示空列表；其他字段不能为空。
- 保存时校验字段类型、时间、范围及关联条件，有误时提示具体配置项并保留弹窗；不会将错误值写入文件。
- 点击“取消”或关闭弹窗时，如有未保存修改，可选择保存、放弃或继续编辑。写入失败时保留原文件，弹窗仍可修改和重试。

全部规则和公司放假安排只保存在一份 `config.json` 中，格式由程序维护。`config.example.json` 是完整默认模板，不会自动读取。JSON 严格校验未知/缺失/重复字段、类型、日期及数值，不将缺失字段当默认值；已选文件损坏或丢失时直接报错。旧 CSV/TOML 不参与读取；旧版自定义规则须在新窗口核对录入，不能只修改扩展名。

命令行配置查找顺序为：当前目录 `config.json` → EXE 所在目录 `config.json`。只读取命中的一份；也可通过 `-c 其他目录\config.json` 指定配置。命令行未找到配置时使用内置默认值并明确提示；桌面窗口使用下文的路径记忆规则。运行日志会显示实际配置路径。

## 配置公司全天或半天放假

点击“编辑公司放假”，在独立弹窗中添加或删除放假日，每项直接填写日期、选择“全天／上午／下午”、填写备注，然后点击“保存并关闭”。留空列表表示没有公司假；新增空行需填完或删除后再保存。以下日期仅为填写示例：

| 日期 | 时段 | 备注 |
| --- | --- | --- |
| 2026-10-16 | 全天 | 公司统一放假 |
| 2026-10-19 | 上午 | 上午活动 |
| 2026-10-20 | 下午 | 提前放假 |

- **全天**：覆盖钉钉正常工作排班，无需打卡，不计迟到、请假；实际来工作时按休息日加班规则，扣午休、按非工作日晚餐配置扣除，并要求审批。
- **上午**：午休结束后到岗，默认13:30；13:45到算迟到15分钟。下班按钉钉原班次，例如18:30，不按下午首卡顺延为19:00。午休开始前实际工作按休息日加班，原班次下班加工作日晚餐后另计工作日加班。例如09:30–22:00，上午计150分钟休息日加班，晚间19:00–22:00计180分钟工作日加班，共330分钟。
- **下午**：午休开始即可下班，默认12:00。之后到最后有效卡的工作按休息日加班，扣固定午休，晚餐沿用非工作日配置（默认不扣），不再叠加原工作日晚间加班。例如09:30–18:30计300分钟，至22:00计510分钟。
- **请假/外出**：只计算剩余正常工作时段。上午放假时按13:30至原班次下班裁切；下午放假时按弹性上班最早时间09:00至12:00裁切，仍采用审批区间，不各折算3.75小时。普通未配置公司假的日期继续使用原来的审批区间扣午休规则。
- **打卡**：半天公司假不会把有效卡不足的工作日自动放行；仍需成对有效卡计算加班，无卡且没有覆盖剩余工作时段的请假依据时仍列补卡。全天放假无打卡不列缺卡，有实际加班信号但有效卡不足时仍须补卡，审批不能代替打卡。原有首末卡规则继续适用，早退/旷工扣款仍未实现。
- **审批**：半天公司假只拿放假时段的实际加班与对应审批比较，保留原30分钟容差；当晚工作日加班不混入这次比较。工作日与休息日加班分别应用最小分钟和取整后相加。
- **优先级**：法定节假日和原“休息”班次保留整天非工作日规则，不因半天公司假变成另半天需要上班；公司假本身不归为法定节假日。关闭“统计非工作日加班”后，公司假加班也不计，正常工作日晚间部分仍统计。
- **校验**：日期必须为 `YYYY-MM-DD`，时段只能选“全天、上午、下午”。重复日期（含上午/下午各一项）、非法日期、未填完整的新增项都会报错并保留弹窗。两段都放假请只填一项“全天”。

公司假保存在当前 `config.json` 的 `company_holidays` 列表中；两个弹窗分别保留另一类设置的最新内容，不再读取单独的公司假 CSV。

报表的总览和每日汇总分别汇总工作日、休息日加班；员工明细和加班明细另列公司放假时段、说明、加班分钟、迟到抵扣和当天应出勤分钟，“配置”页保留完整公司假安排。

## 目录结构

- `attendance_analyzer/`：分析源码包。
- `tests/`：自动化测试。
- `scripts/`：打包脚本。
- `input/`：待分析的钉钉 Excel；实际考勤文件只保存在本地，不提交到 Git。
- `output/`：分析结果；历史结果可放在 `output/archive/`，也不提交到 Git。
- `main.py`：桌面窗口和 EXE 的顶层入口。
- `build_release.bat`：开发机的一键打包入口，输出 ZIP。
- `config.json`：当前使用的全部考勤规则和公司放假安排；`config.example.json`：完整默认模板。

打包为 `.exe` 后，首次打开默认选中 `input` 和 `output` 目录；之后恢复上次的考勤输入目录、结果输出目录和 JSON 配置路径。输入和输出均须填写目录；旧记录若保存的是单个文件，需重新选择目录后开始统计。

## 设计

- `config.py`：严格读取、校验并原子保存 JSON 配置。
- `excel_reader.py`：把钉钉工作簿解析成类型明确的每日记录和原始打卡记录。
- `rules.py`：负责单日加班、迟到原始分钟和审批差异计算。
- `analyzer.py`：编排读取器和规则计算，并按员工/月分配迟到宽限。
- `report_writer.py`：写出最终分析工作簿。
- `cli.py`：命令行入口和窗口共用的执行流程。
- `gui.py`：HR 窗口、后台执行、阶段进度、可复制详情和运行日志。
- `config_editor.py`：考勤规则表单和公司放假列表弹窗。
- `main.py`：桌面 EXE 的顶层入口，避免直接打包包内模块时出现相对导入问题。

## 输出内容

输出 Excel 包含：

- `加班明细`：每天每人的加班计算结果，并包含计算说明。
- `员工汇总`：按员工汇总加班天数、分钟、小时、迟到次数、迟到原始分钟、宽限分钟、扣款迟到分钟，以及待补卡/待审核状态。
- `每日汇总`：按日期汇总加班人数、分钟、小时和迟到分钟，以及待补卡/待审核状态。
- `待补卡通知`：可直接交给 HR 的补卡通知清单；补卡后重新导出并再次运行。
- `待审核清单`：审批与实际打卡差异超过容差，或非工作日缺少可解析加班申请的记录，并标记是否需要通知 HR。
- `异常数据`：提示缺卡但有原始记录、有效打卡不足、审批差异等需要人工复核的数据。
- `待人工确认`：记录明确被规则排除的无效卡、补卡审批等业务提示。解析失败的输入会直接报错并停止该文件统计，修正后重跑；不会仅留提示就继续计算。
- `配置`：记录本次分析使用的关键规则。

## 打包 EXE

在 Windows 64 位开发机安装 Python（含 Tcl/Tk，且已加入 PATH），双击 **`build_release.bat`** 即可一键打包。首次打包需联网安装依赖。HR 机器无需安装 Python，也无需联网统计；查看报表可使用 Excel/WPS，编辑规则使用内置弹窗。

也可在命令行执行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_exe.ps1
```

脚本会安装依赖、校验 JSON、运行测试、构建不带控制台的 EXE，并生成 `dist\dingding-attendance.zip`。打包失败会保留错误信息，退出码为非零；不要把之前的旧 ZIP 当成本次新版本。

ZIP 解压后的结构如下，模板集中在独立目录，不自动读取：

```text
dist\dingding-attendance\
  dingding-attendance.exe
  config.json
  使用说明.txt
  配置模板\
    config.json
  input\
  output\
  logs\
```

ZIP 使用明确文件清单生成，`input`、`output`、`logs` 在 ZIP 内始终为空，不会带入开发机上的实际考勤、报表和日志；当前正式 JSON 中的规则和公司假安排会随包分发。

将 ZIP 发给 HR，右键“全部解压缩”到桌面等可写目录后双击 EXE，不要在压缩包里直接运行。打开窗口后选择考勤输入目录和结果输出目录，确认规则，再开始统计。也支持用参数预选这两个目录：

```powershell
dingding-attendance.exe "考勤目录" -c config.json -o output
```

窗口每次在所选结果位置新建 `统计_日期_时间` 子目录。失败后弹出一次简短提示，完整错误和配置路径保留在窗口详情及 `logs` 文件中；支持复制详情、打开日志。批量遇错停止，显示已完成数量，之前的成功结果保留，后续文件未处理。

HR 可通过“选择配置文件”选择另一份 JSON；两个编辑弹窗均针对当前选中的文件。需要恢复默认配置时，可从“配置模板”复制 `config.json`，恢复前请保留自己的规则和公司假安排。

窗口启动优先级为：显式启动参数 → 上次保存的路径 → EXE 同目录默认路径。选择输入目录、输出目录或 JSON 配置后自动记住，手动输入路径在开始统计或正常关闭时保存。`window_paths.json` 只在本地保存这三个路径，不存考勤规则，不会加入 Git 或发布 ZIP。保存失败会提示下次可能需重选，但本次仍可统计；记录损坏会提示检查恢复的路径。已记住的配置被移动或删除时直接报错，需重新选择，不会自动改用其他规则。软件目录移动后也请核对保存的路径。
