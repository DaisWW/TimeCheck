# HR 使用交互与发布方式

目标环境为 Windows 10/11 64 位电脑。开发机打包一次后发送 ZIP，HR 完整解压后即可使用，无需 Python、管理员权限或联网统计；查看报表和编辑配置可用 Excel/WPS。干净新电脑的兼容性仍需在实际目标机器验证。

## 交互选择

| 方式 | 使用特点 | 本项目选择 |
| --- | --- | --- |
| BAT 控制台 | 适合查看完整输出，但路径参数、长错误和窗口关闭行为对 HR 不直观 | 开发机保留命令行入口，发生错误时暂停 |
| 仅添加错误弹窗 | 短提示醒目，但放不下大量错误，也不能显示进度和回看详情 | 仅用于提醒失败，完整内容留在主窗口 |
| 简洁桌面窗口 | 可以选文件、显示状态、复制详情、打开结果，并保留错误上下文 | HR 的默认入口；使用随 Python 打包的 Tk，直接调用现有统计代码 |

不另外建立一套考勤计算。窗口和命令行共用 CSV 读取、审批解析、考勤规则与 Excel 输出逻辑，差别仅在路径选择、进度显示、日志和结果保存位置。

## 操作流程

1. 双击 EXE，默认选择同目录 `input` 和 `output`，也可选择单文件或其他目录。
2. 窗口显示基础 CSV 路径，并提供两个配置文件的打开按钮。HR 修改并保存 CSV 后再开始。
3. 点击开始，后台线程读取和计算，主窗口继续响应；运行期间锁定路径与开始按钮，避免同一窗口重复执行。
4. 忙碌条表示正在处理，不表示时间百分比；状态显示“读取和计算”“生成报表”，另显示实际已完成 X/Y 个文件。
5. 成功后显示完成文件数，点击打开本次结果。待补卡、待审核等业务问题继续由 Excel 清单呈现。
6. 失败后状态显示失败原因和已完成数量，只弹一次简短通知；详情保留，可复制或打开本地日志，修正后重新开始。

每次运行新建带时间的结果子目录。失败不会把旧目录显示为本次成功，也不会把已有历史报表混在新结果中。批量遇错停止，之前成功的文件保留，后续文件未处理。运行中不提供强制取消，关闭窗口时提示等待，避免打断报表写入。

## 错误呈现

| 场景 | 展示及处理 |
| --- | --- |
| 基础 CSV 缺失、格式错误、未知项 | 明确显示路径/行号/原值，停止；窗口不回退到内置默认值或模板 |
| 公司放假配置错误 | 显示 CSV 行号、日期/时段原值，停止；文件缺失表示未配置公司假 |
| Excel 无法读取、缺表/缺列、无法解析审批或打卡 | 显示源文件、工作表、行号、字段、原值及原因；可识别的阻断问题在同一文件中集中列出，失败文件不生成统计结果 |
| 输出被占用、无权限、磁盘空间不足 | 保留实际系统错误，提示关闭 Excel、调整权限或更换保存目录后重试 |
| 没有文件、路径无效 | 提示重新选择文件或目录 |
| 程序意外错误 | 明确显示未完成并保存异常堆栈，不弹出“成功”；维护人员可通过日志排查 |
| 缺卡、审批差异、病假/婚假工资分类待确认 | 属于业务审核，生成报表并进入待补卡、待审核等清单；成功提示提醒 HR 查看清单 |

每次运行一份 UTF-8 日志，窗口和日志记录相同的详细输出，包含实际配置路径和结果目录；意外错误额外保留堆栈。日志目录不可写时，在开始计算前报错并提示解压到可写目录。日志不联网发送，可能包含员工信息和输入原值，按公司考勤资料要求保管。

## 一键发布

开发机双击 `build_release.bat`，顺序执行依赖安装、CSV 校验、回归测试、PyInstaller 打包、ZIP 生成与完整性检查。失败返回非零并保留控制台，之前的 ZIP 不代表本次构建成功。

ZIP 只收录 EXE、两份正式 CSV、使用说明、独立配置模板和空的 `input/output/logs` 目录，避免将本地实际考勤、历史结果或日志打包。正式 CSV 属于发布内容，更新现有部署时 HR 需要保留自己的规则和公司假安排。

## 已验证范围

107 项自动化测试通过；窗口通过后台线程成功生成真实报表、失败后保留详情并恢复按钮的验证。实际 ZIP 已解压到含中文和空格的新目录，通过打包后的 EXE 验证成功生成报表，以及批量第二个文件审批解析失败时显示“已完成1/2”、停止处理、保留行号和原值日志。ZIP 完整性与文件清单检查通过，未加入实际业务数据。

补充发布验收：使用 `d49c437` 对应 ZIP 再次解压，子进程 PATH 仅保留 Windows System32，不携带 Python、虚拟环境或 Tcl/Tk 环境变量，并使用独立临时目录。从另一个含错误 `config.csv` 的工作目录启动，窗口仍读取 EXE 旁的正式配置，样例统计得到 60 分钟加班且报表可正常回读。进程加载的 Python、Tcl/Tk 模块均位于打包程序的 `_MEI` 临时解压目录。加入第二份错误审批样例后，界面显示已完成1/2、退出码4，日志保留源行号和原值，失败文件未生成结果，按钮恢复可用。

以上验证在当前 Windows 开发机完成；尚未在没有 Python 的独立新电脑上实测。发布程序已包含 Python、Tcl/Tk 和统计依赖。
