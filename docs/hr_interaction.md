# HR 使用交互与发布方式

目标环境为 Windows 10/11 64 位电脑。开发机打包一次后发送 ZIP，HR 完整解压后即可使用，无需 Python、管理员权限或联网统计；编辑配置使用内置弹窗，查看报表可用 Excel/WPS。干净新电脑的兼容性仍需在实际目标机器验证。

## 交互选择

| 方式 | 使用特点 | 本项目选择 |
| --- | --- | --- |
| BAT 控制台 | 适合查看完整输出，但路径参数、长错误和窗口关闭行为对 HR 不直观 | 开发机保留命令行入口，发生错误时暂停 |
| 仅添加错误弹窗 | 短提示醒目，但放不下大量错误，也不能显示进度和回看详情 | 仅用于提醒失败，完整内容留在主窗口 |
| 简洁桌面窗口 | 可以选目录、显示状态、复制详情、打开结果，并保留错误上下文 | HR 的默认入口；使用随 Python 打包的 Tk，直接调用现有统计代码 |

窗口和命令行共用 JSON 配置、审批解析、考勤规则与 Excel 输出逻辑，差别仅在路径选择、配置表单、进度显示、日志和结果保存位置。

## 操作流程

1. 首次双击 EXE，默认选择同目录 `input` 和 `output`；之后恢复上次的考勤输入目录、结果输出目录和 JSON 配置路径，启动参数优先覆盖对应路径。窗口只选择目录，批量处理输入目录第一层的全部 `.xlsx` / `.xlsm`，跳过 Excel 临时文件和已有报表，不扫描子目录。
2. 窗口显示当前配置路径，可通过“选择配置文件”更换。点击“编辑考勤规则”打开中文分类表单，点击“编辑公司放假”打开可直接增删的日期/时段/备注列表；两个弹窗均点击“保存并关闭”后生效。
3. 点击开始，后台线程读取和计算，主窗口继续响应；运行期间锁定路径与开始按钮，避免同一窗口重复执行。
4. 忙碌条表示正在处理，不表示时间百分比；状态显示“读取和计算”“生成报表”，另显示实际已完成 X/Y 个文件。
5. 成功后显示完成文件数，点击打开本次结果。待补卡、待审核等业务问题继续由 Excel 清单呈现。
6. 失败后状态显示失败原因和已完成数量，只弹一次简短通知；详情保留，可复制或打开本地日志，修正后重新开始。

每次运行新建带时间的结果子目录。失败不会把旧目录显示为本次成功，也不会把已有历史报表混在新结果中。批量遇错停止，之前成功的文件保留，后续文件未处理。运行中不提供强制取消，关闭窗口时提示等待，避免打断报表写入。

路径选择后自动保存，手动输入在开始或正常关闭时保存。`window_paths.json` 只记录三个路径，写入通过临时文件替换，失败保留旧记录并提示本次仍可统计；不包含考勤规则，也不进入 Git 或发布 ZIP。记录损坏会提示检查默认路径；已保存的配置丢失时仍指向该路径并报错，避免静默切换规则。软件目录移动后需核对路径。

规则和公司假保存在一份 `config.json`。规则弹窗覆盖全部22项，开关使用勾选、取整方式使用下拉框，其余字段带格式说明。公司假逐行编辑，无需额外“加入列表”；新增空行须填写或删除，保存时拦截重复日期。关闭有修改的弹窗时可保存、放弃或继续编辑。保存前校验全部数据，使用临时文件原子替换；失败保留原文件并保持弹窗。两个弹窗保存时重新读取文件，保留另一类设置的最新内容。

仅使用 JSON 配置；旧 CSV/TOML 不再读取。旧版路径仍指向 CSV 时需重新选择 JSON，旧自定义规则请在表单中核对录入，不自动迁移或静默改用默认规则。

## 错误呈现

| 场景 | 展示及处理 |
| --- | --- |
| JSON 缺失、语法错误、重复/未知/缺失字段、错误类型 | 明确显示文件及具体字段，JSON语法错误含行列号；停止，窗口不回退到默认值或模板 |
| 规则表单填写错误 | 显示中文配置项及原因，定位相应标签页和输入框，保留未保存内容 |
| 公司假日期非法、时段非法、日期重复 | 显示第几项、原值及原因，保留列表；空列表表示未配置公司假 |
| 配置写入失败 | 保留原配置并保持弹窗，可修正权限或重试；不会提示已保存 |
| Excel 无法读取、缺表/缺列、无法解析审批或打卡 | 显示源文件、工作表、行号、字段、原值及原因；可识别的阻断问题在同一文件中集中列出，失败文件不生成统计结果 |
| 输出被占用、无权限、磁盘空间不足 | 保留实际系统错误，提示关闭 Excel、调整权限或更换保存目录后重试 |
| 输入不是已有目录、输出位置是文件 | 开始前提示具体路径并要求重新选择目录；旧版记住的单文件路径也需重选 |
| 目录中没有可处理的文件 | 提示重新选择含考勤文件的输入目录 |
| 程序意外错误 | 明确显示未完成并保存异常堆栈，不弹出“成功”；维护人员可通过日志排查 |
| 缺卡、审批差异、病假/婚假工资分类待确认 | 属于业务审核，生成报表并进入待补卡、待审核等清单；成功提示提醒 HR 查看清单 |

每次运行一份 UTF-8 日志，窗口和日志记录相同的详细输出，包含实际配置路径和结果目录；意外错误额外保留堆栈。日志目录不可写时，在开始计算前报错并提示解压到可写目录。日志不联网发送，可能包含员工信息和输入原值，按公司考勤资料要求保管。

## 一键发布

开发机双击 `build_release.bat`，顺序执行依赖安装、JSON 校验、回归测试、PyInstaller 打包、ZIP 生成与完整性检查。失败返回非零并保留控制台，之前的 ZIP 不代表本次构建成功。

ZIP 只收录 EXE、正式 `config.json`、使用说明、独立默认模板和空的 `input/output/logs` 目录，避免将本地实际考勤、历史结果或日志打包。正式 JSON 属于发布内容，更新现有部署时 HR 需要保留自己的规则和公司假安排。

## 已验证范围

123项自动化测试通过，覆盖 JSON 唯一配置、严格字段及类型校验、原子保存、全部规则表单往返、两个弹窗保存/取消/关闭、非法/重复公司假、保存失败保留文件，以及重新打开恢复和保存时保留另一类设置。原有审批、考勤计算、目录批处理、错误日志和路径记忆回归继续执行。

此前发布验收：使用 `d49c437` 对应的 CSV 版本 ZIP 解压，子进程 PATH 仅保留 Windows System32，不携带 Python、虚拟环境或 Tcl/Tk 环境变量，并使用独立临时目录。从另一个含错误 `config.csv` 的工作目录启动，窗口仍读取 EXE 旁的正式配置，样例统计得到 60 分钟加班且报表可正常回读。进程加载的 Python、Tcl/Tk 模块均位于打包程序的 `_MEI` 临时解压目录。加入第二份错误审批样例后，界面显示已完成1/2、退出码4，日志保留源行号和原值，失败文件未生成结果，按钮恢复可用。

此前路径记忆验证：源码 Tk 窗口验证选择后立即保存、手输路径关闭后保存、重建窗口恢复三条路径及保存失败提示。当时的 ZIP 打包窗口可显示外部中文和空格路径；打包版关闭后重启的人工验证被 Esc 中止，尚未完成。

此前目录模式验证：源码 Tk 窗口通过目录选择、路径保存与后台线程，批量处理一份 `.xlsx` 和一份 `.xlsm`，显示已完成 2/2；两份报表均生成到所选输出目录的本次子目录，可回读且源文件哈希未改变。

当前内置编辑器联调：通过主窗口依次打开两个弹窗并保存，再启动后台统计。工作日晚餐设为0后，样例加班为90分钟；同一天配置下午公司假后，重新统计为390分钟公司假加班，报表可回读且源文件哈希未变。关闭弹窗时主动释放 Tk 变量，回归覆盖其在后台统计前释放，避免工作线程垃圾回收触发 Tcl 调用。

当前 JSON 版本重新构建 ZIP，通过123项测试、文件清单及CRC校验；EXE已包含编辑器模块，正式配置、模板和使用说明与源码一致，包内不含旧CSV、本机路径记录、实际考勤或报表。本轮未重复打包版窗口的人工操作。

以上验证在当前 Windows 开发机完成；尚未在没有 Python 的独立新电脑上实测。发布程序已包含 Python、Tcl/Tk 和统计依赖。
