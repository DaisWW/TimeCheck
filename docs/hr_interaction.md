# HR 使用交互与发布方式

目标环境为 Windows 10/11 64 位电脑。开发机打包一次后发送 ZIP，HR 完整解压后即可使用，无需 Python、管理员权限或联网统计；编辑配置使用内置弹窗，查看报表可用 Excel/WPS。干净新电脑的兼容性仍需在实际目标机器验证。

## 启动入口

| 使用场景 | 入口 | 环境要求 |
| --- | --- | --- |
| 源码直接使用 | 双击 `启动考勤客户端.bat` 打开客户端 | 安装含 Tcl/Tk 的 Python 并加入 PATH，首次安装项目依赖 |
| AI / 自动化统计 | 直接调用 `一键统计考勤.bat`，无需参数 | 安装 Python 和项目依赖；全程无窗口、无按键等待 |
| HR 使用发布版本 | 完整解压 ZIP，双击 `dingding-attendance.exe` | 无需 Python |
| 开发机发布新版本 | 双击 `build_release.bat` 生成 ZIP | 安装 Python；构建时安装依赖并运行测试 |

源码和发布版本使用同一个桌面窗口与统计流程，文件列表、配置编辑、进度、错误详情和结果打开方式一致。日常统计无需重新打包。“启动考勤客户端.bat”仅负责启动窗口；启动失败时保留控制台和原始错误，并提示安装依赖或使用发布版，正常关闭窗口后直接退出。

“一键统计考勤.bat”复用同一统计逻辑，固定处理 BAT 同目录的 `input`，读取统一保存考勤规则与公司放假日的 `config.json`，直接写入 `output`；无需参数，不接受路径覆盖，也不读取窗口路径记录。从其他工作目录调用时仍使用 BAT 同目录的文件。成功或失败均直接返回，不暂停。标准输出/错误采用 UTF-8，退出码用于判断结果；批量遇错停止。同名报表会覆盖，需保留历史时先归档已有结果。

## 操作流程

1. 固定使用软件同目录的 `input`、`output` 和 `config.json`，无需选择目录或记忆路径。旧 `window_paths.json` 不再读取；升级前需将原来外部目录中的数据、配置复制到当前软件目录并核对。源码窗口也使用项目根目录，均不随启动时的工作目录改变。
2. 点击“添加考勤文件…”多选文件，或从资源管理器拖入原始 `.xlsx` / `.xlsm`；复制到 `input`，保留源文件。同名文件可替换、跳过或取消，同一批选择中来自不同目录的同名文件整批拒绝；不导入文件夹、临时文件和分析结果。导入不改写源文件只读属性，副本保持可清理。
3. 左侧显示 input 第一层全部项目及参与状态；子目录不参与统计。点击“开始统计全部”处理全部有效考勤，列表选择仅用于打开和清理。运行期间禁止导入、清理、配置编辑及重复开始；后台计算不阻塞进度和详情刷新。
4. 右侧按批次展示 output，批次可展开查看报表，双击文件打开，选择批次或文件后也可点击“打开所选”。完成后自动刷新并选中本次批次。
5. 两个列表均支持 Ctrl / Shift 多选后“移到回收站”和“清空…”，确认框显示项目名称并明确整批包含全部文件；删除保留 input/output 目录及源码占位文件。误删可从 Windows 回收站恢复，回收失败显示原因和已处理数量，不回退到永久删除。链接和目录联接不得用于导入目标或清理路径。
6. 忙碌条表示正在处理，状态显示实际已完成 X/Y 个文件；详情默认收起，报错自动展开，只弹一次简短通知。可复制详情或打开本地日志，修正后重新开始。

每次运行新建 `output/统计_日期_时间`，避免覆盖历史报表。批量遇错停止，之前成功的文件保留，后续文件未处理。关闭运行中的窗口会提示等待，避免打断报表写入。在资源管理器中修改文件后，可点击“刷新列表”。

规则和公司假保存在一份 `config.json`。规则弹窗覆盖全部22项，开关使用勾选、取整方式使用下拉框，其余字段带格式说明。公司假点击“添加日期或范围…”后，用中文日历选择起止日期，可直接切换年月，支持跨月、跨年；手输日期也会严格校验。统一选择全天/上午/下午、填写备注并确认天数，再加入逐日列表，每天的日期、时段、备注均可独立修改，也可删除。范围包含首尾和周末，单次最多366天；重叠时列出已有日期和时段，整批不加入，保留当前选择。取消范围选择不修改列表，加入列表尚未写入文件。列表支持滚轮，滚动经过时段下拉框时不改变选项。

关闭有修改的公司假或规则弹窗时可保存、放弃或继续编辑。保存前校验全部数据（含逐日修改后的重复日期），使用临时文件原子替换；失败保留原文件并保持弹窗。两个弹窗保存时重新读取文件，保留另一类设置的最新内容。范围选择仅用于批量生成每天的配置，保存结构和考勤算法不变。

仅使用 JSON 配置；旧 CSV/TOML 不再读取。旧自定义规则请在表单中核对录入，不自动迁移或静默改用默认规则。

## 错误呈现

| 场景 | 展示及处理 |
| --- | --- |
| JSON 缺失、语法错误、重复/未知/缺失字段、错误类型 | 明确显示文件及具体字段，JSON语法错误含行列号；停止，窗口不回退到默认值或模板 |
| 规则表单填写错误 | 显示中文配置项及原因，定位相应标签页和输入框，保留未保存内容 |
| 公司假日期非法、时段非法、日期重复 | 显示第几项、原值及原因，保留列表；空列表表示未配置公司假 |
| 公司假范围倒序、非法、超过366天或重叠 | 显示起止字段或冲突日期及已有时段，保留范围输入；不会部分加入或覆盖已有安排 |
| 配置写入失败 | 保留原配置并保持弹窗，可修正权限或重试；不会提示已保存 |
| Excel 无法读取、缺表/缺列、无法解析审批或打卡 | 显示源文件、工作表、行号、字段、原值及原因；可识别的阻断问题在同一文件中集中列出，失败文件不生成统计结果 |
| 输出被占用、无权限、磁盘空间不足 | 保留实际系统错误，提示关闭 Excel、检查权限和空间后重试；软件应完整解压到可写目录 |
| input/output 被同名文件占用或为目录联接 | 显示具体路径并停止，需修正软件同目录的数据目录 |
| input 中没有可处理的文件 | 开始前提示添加或拖入钉钉原始考勤 |
| 导入格式不支持、同批重名、复制失败 | 列出文件和原因；格式或名称预检失败不复制，系统失败显示已添加数量；同名替换使用临时文件，失败保留旧副本 |
| 清理取消、文件占用或无权限 | 取消不操作，失败保留未清理项目并刷新列表，只允许管理 input/output 内项目 |
| 程序意外错误 | 明确显示未完成并保存异常堆栈，不弹出“成功”；维护人员可通过日志排查 |
| 缺卡、审批差异、病假/婚假工资分类待确认 | 属于业务审核，生成报表并进入待补卡、待审核等清单；成功提示提醒 HR 查看清单 |

每次运行一份 UTF-8 日志，窗口和日志记录相同的详细输出，包含实际配置路径和结果目录；意外错误额外保留堆栈。日志目录不可写时，在开始计算前报错并提示解压到可写目录。日志不联网发送，可能包含员工信息和输入原值，按公司考勤资料要求保管。

## 一键发布

开发机双击 `build_release.bat`，顺序执行依赖安装、JSON 校验、回归测试、PyInstaller 打包、ZIP 生成与完整性检查。成品为 `build/dingding-attendance.zip`，发布目录为 `build/dingding-attendance/`，中间文件放在 `build/pyinstaller/`；整个 `build/` 已被 Git 忽略。失败返回非零并保留控制台，之前的 ZIP 不代表本次构建成功。

ZIP 只收录 EXE、正式 `config.json`、使用说明、独立默认模板和空的 `input/output/logs` 目录，避免将本地实际考勤、历史结果或日志打包。正式 JSON 属于发布内容，更新现有部署时 HR 需要保留自己的规则和公司假安排。

## 已验证范围

133项自动化测试通过，覆盖 JSON 唯一配置、严格字段及类型校验、原子保存、全部规则表单往返、两个弹窗保存/取消/关闭、非法/重复公司假、保存失败保留文件，以及重新打开恢复和保存时保留另一类设置。新增范围验证覆盖跨月、跨年、周末、闰日、倒序、过长范围、重叠整批拒绝、逐日改期与时段、日历年月输入及模态窗口和 Tk 变量释放。正式配置允许 HR 自定义，默认模板仍核对全部默认值。原有审批、考勤计算、目录批处理和错误日志回归继续执行；原路径记忆由固定目录规则替代。

此前发布验收：使用 `d49c437` 对应的 CSV 版本 ZIP 解压，子进程 PATH 仅保留 Windows System32，不携带 Python、虚拟环境或 Tcl/Tk 环境变量，并使用独立临时目录。从另一个含错误 `config.csv` 的工作目录启动，窗口仍读取 EXE 旁的正式配置，样例统计得到 60 分钟加班且报表可正常回读。进程加载的 Python、Tcl/Tk 模块均位于打包程序的 `_MEI` 临时解压目录。加入第二份错误审批样例后，界面显示已完成1/2、退出码4，日志保留源行号和原值，失败文件未生成结果，按钮恢复可用。

此前路径记忆验证：源码 Tk 窗口验证选择后立即保存、手输路径关闭后保存、重建窗口恢复三条路径及保存失败提示。当时的 ZIP 打包窗口可显示外部中文和空格路径；打包版关闭后重启的人工验证被 Esc 中止，尚未完成。

此前目录模式验证：源码 Tk 窗口通过目录选择、路径保存与后台线程，批量处理一份 `.xlsx` 和一份 `.xlsm`，显示已完成 2/2；两份报表均生成到所选输出目录的本次子目录，可回读且源文件哈希未改变。

当前内置编辑器联调：通过主窗口依次打开两个弹窗并保存，再启动后台统计。工作日晚餐设为0后，样例加班为90分钟；同一天配置下午公司假后，重新统计为390分钟公司假加班，报表可回读且源文件哈希未变。关闭弹窗时主动释放 Tk 变量，回归覆盖其在后台统计前释放，避免工作线程垃圾回收触发 Tcl 调用。

以上验证在当前 Windows 开发机完成；尚未在没有 Python 的独立新电脑上实测。发布程序已包含 Python、Tcl/Tk 和统计依赖。
